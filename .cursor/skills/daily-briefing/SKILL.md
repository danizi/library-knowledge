# AI 每日新闻简报

先查当天数据，再写 HTML。星标必须来自本次查询，禁止沿用旧数字或编造。

## 步骤

1. 打开 GitHub Trending（`since=daily`）。跳过明显的越狱、破解、投毒仓库。
2. 对入选仓库再查 GitHub API（`stargazers_count`、`description`、`html_url`）。页面上的数字和 API 不一致时，以 API 为准。
3. 热门按星标从高到低取 9 个。再单独查反编译 / 逆向方向的开源仓库，优先带 AI 或 MCP 的，至少 6 个，同样走 API。每个仓库读 README 开头，抽出「是什么」和「怎么用」。README 没写清命令时，只写仓库里确实有的用法，不补想象的命令。
4. 写单页 HTML 到 `.cursor/docs/briefings/YYYY-MM-DD.html`（用用户环境当天的日期）。
5. 回复里给出该文件的绝对路径，并用浏览器打开。

## 第一节：GitHub 热门（必写，放在最前）

每条都要有：

- 项目名和仓库链接
- 星标（Stars）。写明这是星标，不是 Watch / Follow
- 一句话：这个项目是什么
- 功能：两三句
- 如何使用：最多 4 步，命令用代码样式

页顶注明：名单来自当天 Trending，星标查询时间写到分钟。

## 第二节：反编译（必写）

标题写明「反编译与逆向」。只收开源仓库。商业反编译器本体（如 IDA Pro）若只是被开源插件连接，要写清「插件开源，本体不是」。经典引擎可以收录，但标明它是反编译器，不是大模型。这一节每次都要包含 <code>morluto/rea</code>（Reverse Engineer Anything，安装命令 <code>npx rea-agents setup</code>），以及 radare2 和它的 AI 插件 r2ai（decai）。不要只写 Ghidra。同名拷贝仓库不要收。

每条同样要有：项目名、链接、星标、是什么、功能、如何使用。

## HTML

单文件，CSS 写在 `<style>` 里，不引用外部字体、样式或脚本。要能扫读，不要成一篇纯文字：

- 页首：标题、日期、来源、页内目录（跳到两大节）
- 宽屏两列卡片，窄屏一列
- 每张卡：序号、仓库名、完整的 `https://github.com/...` 地址（地址本身要写出来，不能只做成仓库名链接）、星标大号、forks、是什么、怎么用
- 两节用不同的顶边区分，节首有一句本节在选什么
- 页脚：当天快照，不要手改星标

## 不做

- 不把简报写进 `knowledge/` 正式卡
- 不改写费曼卡或 INDEX，除非用户另外要求
