# 任务
在 `### CP · ContentProvider` 整节之后、`### V · View` 之前，新增 `### BT · Bluetooth`。
从入门排到一次 GATT 读写。结构与 ACT 相同：
1. `knowledge/Android/BT学习计划.md`：每天约 3 小时，到点停。每天一行总览，列主题、产出、对应题号。每天日程是「输入 → 一个 Demo → 一张卡 → 默答」。D0 是工程跑通。倒数第二天是题库默答，最后一天是复跑。原则写上：Demo 不过不写卡。
2. `knowledge/Android/BT面试题库.md`：按天列出必刷题号。题分成必会和选做。每题写场景，不写背诵条文。API 和行为以 Android 开发者文档为准，每题在参考里给出出处。写不出出处的题不要编进题库。
3. `knowledge/Android/BT错题库.md`：只建用法和空表，列：题、我当时的坑、要说的那句、相关、记于。表体留空。没有人答错过，不要填坑。
4. Demo：计划里的每一天一个独立工程，放在 `knowledge/Android/demos/bluetooth/bt-d{天}-{主题}/`。工程能指出 `settings.gradle.kts` 和 app 模块。D0 只要求装好权限声明并跑起一个空界面。后面每天只加当天那一个行为。
5. 知识卡：父卡 `BT-001 | 蓝牙.md`，子卡一天一张，对上计划里的主题。写完在 INDEX 挂上，注记「仍待审查」。
6. 改 INDEX 之前再搜一遍 `BT-` 和 `蓝牙`。已经有同名文件或同号卡片就停，不要覆盖。

# 输出格式
先写 INDEX 里 `### BT · Bluetooth` 这一节的全文，顺序固定为：学习计划、面试题库、错题库、Demo 列表、BT-001 和子卡。
然后按这个顺序写文件：学习计划、面试题库、错题库、每张卡、每个 Demo 的源文件。
每个文件开头单独一行写路径。
不要写这套文件以外的说明。

输出：`BT错题库.md` 只保留用法和空表。不写「我当时把扫描权限说成定位权限」这类句子。

# 注意
- 不改 ACT、FG、SVC、BR、CP 的计划、题库、卡片和 Demo。蓝牙是新的一节。
- 不编造错题。错题库是给人以后记自己答歪的原句，现在填了就无法再当复盘。
- 不写没有文档出处的 API 行为。蓝牙权限随系统版本变化，答错了后面的 Demo 和面试题会对不上。
- 一天不要塞两个 Demo。ACT 是一天一个工程，蓝牙沿用这个节奏，否则计划里的「产出」对不上目录。
- 卡片编号和 Demo 的天序号从 001 和 d0 起。不要接在 ACT-001 或 act-d5 后面。
- 新 INDEX 行写「仍待审查」。不要写成「仍待审卡」，规则文件里的用词是「仍待审查」。
