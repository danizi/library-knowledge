# 声明式与命令式对比

**问：** 写 Android UI 时，「命令式」和「声明式」差在哪？为啥 Compose 叫声明式？

**答：**  
- **命令式（传统 View）**：你一步步下令——找到控件、改文字、设可见性、再改一次……UI 是「被你改出来的」。  
- **声明式（Compose）**：你描述「当前状态下 UI 应该是什么」；状态变了，框架负责对齐到新描述。  

一句话：命令式管「怎么改」；声明式管「是什么」。

**例：**  
计数器 +1：  
- 命令式：`textView.text = (count++).toString()`  
- 声明式：`var count by remember { mutableStateOf(0) }`，UI 写 `Text("$count")`，点按钮只改 `count`。

**易错：**
- 在 Compose 里继续「握着控件引用改」会对不上重组模型。
- 声明式不等于不能写逻辑；逻辑应推动**状态**，再由状态推出 UI。
