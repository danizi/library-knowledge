# 写特征

**问：**
为什么 `writeCharacteristic` 返回之后，还不能说设备已经收下了这个字节？

**答：**
API 33 起用 `writeCharacteristic(characteristic, value, writeType)`。`WRITE_TYPE_DEFAULT` 表示要应答的写。这个方法返回的是请求有没有交出去，例如缺少 `BLUETOOTH_CONNECT` 时会返回缺少权限的状态码。设备侧的结果在 `onCharacteristicWrite` 里，status 为 `GATT_SUCCESS` 才算这次写完成。`GATT_WRITE_NOT_PERMITTED` 表示这个特征不允许写。Punch Through 的实战建议是：上一次读或写的回调回来之前，不要发下一次。

一句话：写是异步的；WRITE_TYPE_DEFAULT 要等 onCharacteristicWrite 里的 GATT_SUCCESS。

**例 / 类比：**
- 例子：bt-d7 只写一个字节 `0x01`，等一次 `onCharacteristicWrite`，不连续写第二下。
- 类比：把信投进邮筒只说明邮筒收了，回执才说明对方签收。

**易错：**
- 把方法返回值当成设备已经处理完。
- 特征只支持无应答写时仍只用 `WRITE_TYPE_DEFAULT`。属性要先看。
