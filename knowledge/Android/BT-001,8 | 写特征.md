# 写特征

**问：** `writeCharacteristic` 返回之后，为什么还不能说设备已经收下这个字节？

> **一句话：** 写入是异步的。`WRITE_TYPE_DEFAULT` 要等 `onCharacteristicWrite` 中的 `GATT_SUCCESS`。

**例：** `bt-d7-write` 只写入一个字节 `0x01`。它等待一次 `onCharacteristicWrite`。它不写入第二个字节。

<details>
<summary>答</summary>

从 API 33 起，调用 `writeCharacteristic(characteristic, value, writeType)`。
`WRITE_TYPE_DEFAULT` 是需要应答的写入。
方法返回值表示请求是否已提交。
缺少 `BLUETOOTH_CONNECT` 时，返回值表示缺少权限。
设备侧结果在 `onCharacteristicWrite` 中。
status 是 `GATT_SUCCESS` 时，这次写入完成。
status 是 `GATT_WRITE_NOT_PERMITTED` 时，这个特征不允许写入。
上一次读取或写入的回调到达之前，不要发送下一次 GATT 操作。

</details>

<details>
<summary>类比</summary>

投入邮筒只表示邮筒收下信件。回执才表示对方签收。

</details>

<details>
<summary>易错</summary>

- 不要把方法返回值当作设备已经处理完成。
- 特征只支持无应答写入时，不要只使用 `WRITE_TYPE_DEFAULT`。
- 写入之前先检查特征属性。

</details>
