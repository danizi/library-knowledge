## 1. 真题

| # | 真题 | 要答到的点 | 落点 |
|---|------|------------|------|
| BR1 | BroadcastReceiver 是啥？ | 收系统/应用广播的组件；`onReceive` 短时 | `BR-001` |
| BR2 | Manifest 静态注册现在有啥坑？ | 多数隐式广播被限制；显式/少数例外 | 同上 · br-d1 |
| BR3 | 动态注册怎么做？ | `registerReceiver`；Context 选对 | `BR-001,1` · br-d2 |
| BR4 | 为啥必须 unregister？ | 防泄漏；常跟 Activity 生命周期 | 同上 |
| BR5 | 有序广播和普通差在哪？ | 可设优先级、可中止传递 | `BR-001,2` · br-d3 |
| BR6 | `exported` / 权限怎么防被乱调？ | 收紧导出；自定义 permission | 同上 |
| BR7 | 进程内通信还用全局广播吗？ | 少用；优先 API / Flow / 本地机制 | `BR-001,3` · br-d4 |
| BR8 | LocalBroadcastManager？ | 已弃用；别当新方案 | 同上 |
| BR9 | `onReceive` 里能开长任务吗？ | 不宜；要去 Service/WM，且注意后台限制 | 选做 |
| BR10 | 与通知 / 深链场景交界 | 点到：事件入口未必再用广播 | 选做 |

### 降温

背全量系统 Action 列表；坚持「静态注册万能」。
