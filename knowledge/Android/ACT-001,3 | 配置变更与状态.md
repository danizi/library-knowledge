# 配置变更与状态

**问：**
旋转屏幕时发生了什么、数据放哪才还在？配置变更和进程被杀（process death）差在哪？

**答：**
旋转是配置变更：Activity **可以 Destroy 再 Create 新实例**。成员变量、`remember { }` 默认丢掉。  
业务态放 **ViewModel**：它跟的是 Owner（还在的任务），不跟那一个 Activity 实例，所以旋转后数还在。勾选、滚动位置这类轻量 UI 用 `rememberSaveable` / `onSaveInstanceState` / `SavedStateHandle`。别把大对象塞 Bundle。  
进程被杀后内存全没，**ViewModel 也死**。要恢复只能靠 SavedState（仍轻量）或磁盘（DataStore/DB）。所以不能说「有 ViewModel 就永远不丢」。

一句话：旋转 ViewModel 常还在；杀进程内存没了，要靠 SavedState 或磁盘。

**例 / 类比：**
- 例子（`stage4-survive-rotate`）：两计数都点到 3，旋转后 ViewModel 仍是 3，`remember` 归 0。
- 类比：换房间（旋转）行李还在前台寄存（ViewModel）；整栋楼停电（杀进程）寄存柜也断电，重要的得放保险柜（磁盘）。

**易错：**
- 把 `remember` 当持久化。
- 以为 ViewModel 能抗进程死亡。
- 大图、列表塞进 `onSaveInstanceState`，Binder/事务会炸或变慢。
- 业务堆在 Activity 字段里，一转屏就丢（链 AAP-001）。
