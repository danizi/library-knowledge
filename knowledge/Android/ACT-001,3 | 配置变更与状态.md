# 配置变更与状态

**问：** 旋转屏幕时，哪些数据还在，哪些数据会丢失？

> **一句话：** 旋转后 ViewModel 通常还在。进程被杀死后，用 SavedState 或磁盘恢复数据。

**例：** `act-d4-survive-rotate` 里，两个计数都点到 3。旋转后，ViewModel 的计数仍是 3。`remember` 的计数回到 0。

<details>
<summary>答</summary>

旋转屏幕是配置变更。
系统可以销毁当前 Activity，再创建新实例。
成员变量默认丢失。
`remember { }` 的值默认丢失。
把业务状态放在 ViewModel 中。
ViewModel 跟随还在的 Owner。
ViewModel 不跟随被销毁的那一个 Activity 实例。
因此旋转后，ViewModel 中的数据还在。
勾选状态和滚动位置使用 `rememberSaveable`、`onSaveInstanceState` 或 `SavedStateHandle`。
不要把大对象放进 Bundle。
进程被杀死后，内存中的数据都丢失。
进程被杀死后，ViewModel 也丢失。
要恢复这些数据，使用 SavedState 或磁盘。
SavedState 只保存轻量数据。
磁盘指 DataStore 或数据库。
不要说「有 ViewModel 就永远不丢失数据」。

</details>

<details>
<summary>类比</summary>

换房间（旋转）行李还在前台寄存（ViewModel）；整栋楼停电（杀进程）寄存柜也断电，重要的得放保险柜（磁盘）。

</details>

<details>
<summary>易错</summary>

- 不要把 `remember` 当作持久化。
- 不要认为 ViewModel 能在进程死亡后保留数据。
- 不要把大图或列表放进 `onSaveInstanceState`。
- 不要只把业务数据放在 Activity 字段里。旋转屏幕后这些字段丢失。

</details>
