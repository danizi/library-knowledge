# 工程文件目录

**问：** 日常修改 Android 工程时，主要看哪个目录？

> **一句话：** 日常代码和资源在 `app/src/main`。其余目录大多是构建文件或生成物。

**例：** 改界面时打开 `res/layout`。改逻辑时打开 `java` 或 Kotlin 源码目录。改组件声明时打开 `AndroidManifest.xml`。

<details>
<summary>答</summary>

日常工作几乎都在 `app/src/main/`。
`java/` 放源码。Kotlin 源码也放在源码目录里。
`res/` 放资源。
`AndroidManifest.xml` 放组件声明。
根目录的 `build.gradle` 管理构建。
`settings.gradle` 管理工程包含哪些模块。
`gradle/` 放 Gradle 相关文件。
`.gradle` 是生成物。
`build/` 是生成物。
不要把生成物当作手写源码。
用 Project 视图看目录树。
目录细节会随 Android Studio 的版本变化。先记住这条主干。

</details>

<details>
<summary>类比</summary>

`app/src/main` 是营业厅。`build` 是存放生成物的房间。不要把时间花在生成物上。

</details>

<details>
<summary>易错</summary>

- 不要死记整棵目录树。用到某个目录时再查。
- 不要把 `local.properties` 提交进 Git。它记录本机 SDK 路径。
- 用 Android Studio 打开带有 `settings.gradle` 或 `settings.gradle.kts` 以及 `gradlew` 的那一层。例如打开 `act-d0-hello`。打开上层 `demos/` 不会 Sync。打开上层 `demos/` 也没有 Run。

</details>
