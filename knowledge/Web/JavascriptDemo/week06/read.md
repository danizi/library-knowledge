**第 6 周：前端小项目 1.0（Todo 打磨）**

- 目标：基于 Week05 Todo MVP，完成前端小项目 1.0，补齐过滤视图、空状态、loading/错误提示、基础样式，并完成 README 与 demo 检查。
- 学习产出：可展示的 Todo 前端 1.0 + 本周自测结果（功能/性能/无控制台报错）。

**学习节奏（1 次集中完成，约 180–240 分钟）**
1) 第一阶段（30–40 分钟）：现状回归与基线检查。
2) 第二阶段（90–120 分钟）：功能增强（过滤、空状态、loading/错误）。
3) 第三阶段（40–60 分钟）：样式打磨 + README 与演示准备。
4) 第四阶段（10–20 分钟）：按验收清单自测并记录结果。

**学习步骤（按顺序 + 时长）**
1) 现状回归与基线检查（30–40 分钟）  
   动作：运行 Week05 Todo，逐项验证添加/删除/切换完成/刷新持久化。  
   完成标准：核心 CRUD 与 localStorage 均可用，无明显功能回归。
2) 过滤视图（All / Active / Completed）（30–40 分钟）  
   动作：增加过滤按钮或标签，按完成状态筛选列表，并标记当前激活过滤器。  
   完成标准：三种过滤切换正确，计数与展示一致。
3) 空状态（20–30 分钟）  
   动作：分别处理两类空状态文案：  
   - 列表完全为空时：提示“还没有任务，先添加一条”。  
   - 过滤后为空时：提示“当前筛选下没有任务”。  
   完成标准：两类空状态可区分且不会与列表同时重复显示。
4) loading / 错误提示（30–40 分钟）  
   动作：模拟异步保存（例如 `setTimeout + Promise`），在保存中显示 loading，失败时显示错误并提供重试。  
   完成标准：loading 可见且可结束；错误可见、可清除、可重试；成功后状态一致。
5) 基础样式打磨（20–30 分钟）  
   动作：统一层级与间距，区分完成态文本样式，优化按钮禁用态/悬停态。  
   完成标准：主要交互组件视觉一致，移动端和桌面端均可读、可点。
6) README 与演示准备（20–30 分钟）  
   动作：补充运行方式、功能清单、截图或录屏说明、已知限制。  
   完成标准：他人可按 README 独立运行并理解主要功能点。

**验收清单（自测勾选）**
- [ ] 功能：可添加、删除、切换完成；All/Active/Completed 过滤正确。
- [ ] 交互：空状态文案准确；loading 与错误提示流程完整（出现、消失、重试）。
- [ ] 持久化：刷新后任务与完成状态保留；异常数据不会导致页面崩溃。
- [ ] 质量：主要流程无控制台红错；常见边界输入（空白、重复）处理合理。
- [ ] README：包含安装/运行命令、功能说明、截图或录屏入口、已知问题。

**常见问题与修复建议**
- 过滤计数错误：统一以同一份 `todos` 源数据计算计数，避免展示数组与统计数组不一致。
- 空状态闪烁：先确定过滤结果再渲染，避免先渲染空态后立刻被列表覆盖。
- 错误提示不消失：成功后主动清理错误状态；重试前先重置上一次错误文案。
- loading 一直存在：在 `finally` 中关闭 loading，确保成功/失败分支都能收敛。
- 样式回归：建立最小样式检查顺序（列表、按钮、完成态、空态、错误态）逐项对比。
